# Администрирование HR-проекта

Последнее обновление: 18.08.2026.

Этот раздел нужен владельцу и техническому администратору для безопасных корректировок, диагностики и восстановления HR-сервисов. Он не содержит значений секретов.

## С чего начинать

1. Прочитать [ACCESS_MAP.md](ACCESS_MAP.md) и проверить доступ к нужной системе.
2. По симптомам определить слой в [ARCHITECTURE.md](ARCHITECTURE.md).
3. Выполнять изменение и проверку по [REPAIR_RUNBOOK.md](REPAIR_RUNBOOK.md).
4. Для фото, `/present`, `/rookies` и Telegram дополнительно использовать локальный скилл [podbor-hr-support](../../.agents/skills/podbor-hr-support/SKILL.md).
5. Перед изменением кода прочитать соответствующий `docs/features/FEATURE_*.md` или создать его.

## Быстрая маршрутизация

| Симптом | Сначала проверять | Не делать |
|---|---|---|
| `/present` или `/rookies` отдаёт 404 | Vercel deployment и наличие маршрута в `podbor-sso/app` | Не менять БД |
| Карточки есть, фото нет | `photo_path`, bucket `candidates`, `/api/photo` | Не копировать и не удалять файлы |
| Пропало описание или дата | Ответ `hr-present`, поля `podbor_people` | Не создавать новую таблицу |
| Новичок без фото | уникальное совпадение с активной карточкой презентации | Не связывать неоднозначное ФИО автоматически |
| Telegram-бот молчит | личный чат, webhook, `tg-hr-bot`, активность пользователя | Не выдавать `is_admin=true` |
| `supabase db push` сообщает о разных историях | остановиться и восстановить оригинальные миграции | Не создавать заглушки и не выполнять `migration repair` вслепую |
| После правки экран не изменился | какая Edge Function задеплоена и какой Vercel deployment активен | Не повторять деплой без проверки источника |

## Критические правила

- Production-данные кандидатов не удалять для исправления отображения.
- Не хранить секреты в Markdown, git, скриншотах, SQL-выводе и сообщениях.
- Не смешивать два исходника: Edge Functions находятся в этом репозитории, Next.js-прокси сайта подбора — в отдельном `podbor-sso`.
- Не применять схему БД без миграции и проверки истории.
- После production-изменения проверять фактический домен, Edge Function и связанные пользовательские сценарии.

## Поддержание документов

После изменения домена, project ref, папки исходника, Edge Function, таблицы или процедуры доступа обновить этот раздел в том же коммите. Значения секретов сюда не добавлять даже временно.
