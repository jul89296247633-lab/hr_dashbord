## 🔴 Критичные расхождения (ломают существующее)

### 1. Город = `vacancies.location`, а не новое поле `city`
**Факт (SPEC стр. 2736):** разбивка по городам уже работает через `vacancies.location`. Дашборд подразделений агрегирует по `location`.
**Проблема:** мои спеки вводят `ADD COLUMN city` → дубль, рассинхрон с дашбордом.
**Исправление:** во ВСЕХ местах обеих спек заменить `city` → `location`. Штатная сверка группирует по `location`.

### 2. Фильтр `google_sheet_row IS NOT NULL` исключит заявки и конфиденциальные из аналитики
**Факт (SPEC стр. 2825, 3935):** дашборд и воронка фильтруют `WHERE google_sheet_row IS NOT NULL` — чтобы отсечь фантомов из CSV.
**Проблема:** заявка и конфиденциальная вакансия создаются БЕЗ `google_sheet_row`. Даже став `active`, они не попадут в KPI.
**Исправление:** изменить фильтр аналитики на:
```sql
WHERE (google_sheet_row IS NOT NULL OR internal_ref IS NOT NULL OR requested_by IS NOT NULL)
```
То есть: «реальная вакансия = пришла из Sheets ИЛИ конфиденциальная ИЛИ создана через заявку». Это правка существующих запросов — пометить явно для Claude Code как затронутые файлы.

### 3. Аудит вакансий уже автоматический (триггер)
**Факт (SPEC стр. 1194 + CLAUDE.md правило №10):** `CREATE TRIGGER audit_vacancies` уже пишет в audit_logs. Правило: «не добавляй ручную запись в audit_logs».
**Проблема:** в спеке заявки я писал «действия пишутся в audit_logs» как будто вручную.
**Исправление:** убрать ручной аудит, опираться на существующий триггер. В критериях оставить «изменения аудируются автоматически».

## 🟡 Расхождения по неймингу (путаница, не поломка)

### 4. `/staffing` уже занят под «Укомплектованность» (ручной %)
**Факт (SPEC стр. 1022, 2898):** `/staffing` + таблица `staffing_records` = ручной общий процент укомплектованности 0–100, вносится head вручную.
**Проблема:** моя `staffing_plan` (штат по городам/должностям) — это ДРУГАЯ сущность, но имя пересекается.
**Исправление:** новую фичу назвать «Штатное расписание», раздел `/staffing-plan` или вложенно `/staffing/plan`. Таблица `staffing_plan` — имя ок, не конфликтует с `staffing_records`. В UI чётко разделить: «Укомплектованность» (общий %) ≠ «Штатное расписание» (план по позициям).

### 5. Создание вакансий — паттерн `/api/vacancies`
**Факт (SPEC стр. 1508):** вакансии живут под `app/api/vacancies/route.ts`.
**Исправление:** заявки логичнее положить как `app/api/vacancies/requests/route.ts` (вложенно), а не отдельный top-level `/api/vacancy-requests`. Согласуется со структурой CLAUDE.md.
